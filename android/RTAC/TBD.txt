I have scanned the codebase and identified potential issues and breaking changes that you will need to address when updating the target SDK from 34 to 37 (which includes changes introduced in Android 15 / API 35, Android 16 / API 36, and API 37).
Below is a categorized breakdown of critical runtime crashes, behavioral breaking changes, and API deprecations in your source code.
1. Critical Runtime Crashes & Security Exceptions
A. Foreground Service Missing Permissions & Type
•
Files:
◦
  app/src/main/AndroidManifest.xml
◦
  RtacService.java:L202
•
Issue: Starting in Android 14 (API 34) and strictly enforced in Android 15+ (API 35–37):
i.
startForeground(NID, notif) will throw InvalidForegroundServiceTypeException because <service android:name=".service.RtacService"> in AndroidManifest.xml does not declare android:foregroundServiceType (e.g. connectedDevice, dataSync, or specialUse).
ii.
<uses-permission android:name="android.permission.FOREGROUND_SERVICE" /> and the specific type permission (e.g., FOREGROUND_SERVICE_CONNECTED_DEVICE or FOREGROUND_SERVICE_DATA_SYNC) are missing from AndroidManifest.xml, which will trigger a SecurityException.
iii.
Note that in API 35+, services with foregroundServiceType="dataSync" have a strict 6-hour daily execution timeout.
B. PendingIntent Missing Mutability Flag
•
File:   DigisparkHelper.java:L103
•
Issue:
Java
PendingIntent pi = PendingIntent.getBroadcast(
        mContext, 0, in, PendingIntent.FLAG_UPDATE_CURRENT);
On Android 12+ (API 31+) and targeting SDK 31+, PendingIntent creation requires explicitly setting either PendingIntent.FLAG_MUTABLE or PendingIntent.FLAG_IMMUTABLE. Omitting both causes an immediate IllegalArgumentException crash when checkPermission() is invoked.

2. Mandatory UI & Layout Enforcement (API 35+ Edge-to-Edge)
Default Edge-to-Edge Behavior Enforcement
•
File:   MainActivity.java:L134-142, L249-268
•
Issue: Starting in Android 15 (API 35), apps targeting API 35+ are drawn Edge-to-Edge by default.
◦
The current window inset logic uses deprecated replaceSystemWindowInsets():
Java
insets = insets.replaceSystemWindowInsets(..., 0);
◦
System UI visibility flags (SYSTEM_UI_FLAG_HIDE_NAVIGATION, SYSTEM_UI_FLAG_LAYOUT_FULLSCREEN, SYSTEM_UI_FLAG_IMMERSIVE_STICKY) in hideNavigationBar() are deprecated and ignored on API 35+.
◦
Fix: Update MainActivity to use WindowInsetsCompat / WindowInsetsControllerCompat or androidx.activity.EdgeToEdge to handle system bars and insets.
3. Deprecated APIs & System Behavioral Changes
A. Wi-Fi Programmatic Controls
•
File:   WifiMonitorMixin.java:L94, L106, L109
•
Issue:
◦
mWifiManager.setWifiEnabled(true) always returns false and is non-functional for third-party apps on API 29+.
◦
mWifiManager.getConfiguredNetworks() and mWifiManager.enableNetwork() are restricted and deprecated. Apps must launch Wi-Fi Settings panels via Settings.PANEL_WIFI or use WifiNetworkSpecifier.
◦
Accessing Wi-Fi state/info on API 33+ requires android.permission.NEARBY_WIFI_DEVICES or location permissions.
B. Background Activity Launches from BootReceiver
•
File:   BootReceiver.java:L29-45
•
Issue:
Java
Intent i = new Intent(context, MainActivity.class);
i.setFlags(Intent.FLAG_ACTIVITY_NEW_TASK);
context.startActivity(i);
Starting in Android 10 (API 29) and strictly enforced in Android 14/15/16, apps cannot launch activities directly from background BroadcastReceivers (e.g. BOOT_COMPLETED) without explicit user interaction or high-priority notifications.
C. Legacy Preference Activity & AsyncTask
•
Files:
